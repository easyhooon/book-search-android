# AI 활용

AI 활용 범위는 요구사항 조사, 설계, 코드·테스트·문서 작성과 검증입니다. 개발자는 기술·제품 정책과 AI 결과의 채택·수정 여부를 판단합니다. 제출 시점에 APK 빌드·자동 테스트 140개, Galaxy 핵심 기능, 제출 패키지 검증 완료. 네트워크 오류·태블릿·폴더블의 현재 APK 재검증은 미실행입니다. 상세 범위는 [QA](QA.md), 항목별 상태는 [REQUIREMENTS](REQUIREMENTS.md) 참고.

## 활용한 작업

| 도구 | 맡은 작업 |
| --- | --- |
| Codex | 요구사항·참고 자료 조사, 설계 초안, 코드·문서 대조. 개발자가 승인한 앱 코드·회귀 테스트 작성과 실행, 빌드, 제출 준비 검토, 문서 정리 |
| Claude Code (Claude Opus 5.5) | 구현 사양, Gradle·모듈 구성, 초기 앱 코드·테스트, 실기기 QA 조작, 시연 영상, 제출 ZIP 스크립트·검증 문서 |

개발자의 역할은 기술 선택, 화면 동작·가격 정책, AI 결과 검토, 실제 키 설정과 최종 제출 확인입니다. 실기기 연결과 폴더블을 직접 접고 펴는 동작도 개발자가 수행한 범위입니다. 앱 코드·회귀 테스트 작성과 명령 실행을 AI에 맡긴 범위와 구분합니다.

## AI 결과를 검증한 방법

- **요구사항·소스 대조:** 원문 필수·사용자 추가 요구·제품 선택을 R-ID로 분류. 라이브러리 동작은 공식 문서와 사용 버전 소스로 대조.
- **단위·계층 테스트:** ID·가격·필터 규칙, 검색·페이징 상태, MockWebServer API 계약, Room 저장·관찰·DB 재열기 검증.
- **수명·통합 테스트:** 실제 Soil·key factory·Presenter를 연결한 `SearchRetryTest`, 실제 retain·Soil·Mutation key와 Fake DAO를 연결한 `FavoriteMutationLifecycleTest`로 재시도·접수 명령의 완료·순서·실패 격리·참조 정리 검증. Fake DAO 검증과 실기기 Room 장애 재현은 별개.
- **화면·상태:** Compose 테스트로 내비게이션·retain·창 크기별 배치·saveable 복원 모사 검증. 현재 APK는 Galaxy 핵심 기능 확인. 기존 회전·오프라인·프로세스 복원·태블릿·폴더블 QA는 관련 동작의 소스 유지 여부를 대조해 회귀 근거로 사용하고, 최신 APK에서 다시 실행한 결과와 구분합니다. 변경된 경로의 기기 재검증과 실제 메모리 압박 종료는 별도 한계로 남깁니다([QA](QA.md)).
- **제출 시점 실행 결과:** 자동 테스트 140개 새 실행, 실패·오류·건너뜀 0. 테스트 작성 여부와 실제 실행 범위, 자동 테스트와 기기 결과를 구분해 [QA](QA.md)에 기록.

원문의 JDK 17 실행 조건은 미충족입니다. Java·Kotlin 컴파일 대상은 17이지만 Metro 플러그인·컴파일러 때문에 Gradle daemon과 Android 단위 테스트는 JDK 21을 사용합니다. 구성과 제한은 [SPEC](SPEC.md)의 JDK 기준 참고.

## AI 제안을 그대로 사용하지 않은 개발자 판단

| 주제 | 판단과 구현 |
| --- | --- |
| 화면 상태·수명 | ViewModel 중심 제안 대신 retain + Navigation 3 선택. 얇은 Presenter가 화면 상태를 소유하고 객체 유지와 프로세스 복원 데이터를 구분. 별도 전체 상태 Store 생략 |
| 원격 통신 | Android 전용 HTTP 통신·테스트를 Retrofit·OkHttp로 충족하므로 Ktor 추가 이점이 없다고 판단. 더 익숙한 Retrofit 선택, Soil key에 서비스 주입 |
| 데이터·모듈 경계 | 원격·로컬 구현을 별도 모듈로 분리. Soil key가 데이터 연결을 맡고 단순 위임 Repository 생략. 즐겨찾기는 Room을 단일 상태 기준으로 사용 |
| 상세·저장 수명 | 단건 조회 API가 없어 상세 스냅샷을 내비게이션 키에 저장. 저장 중 이동은 허용하고 접수한 명령 완료 후 참조 정리. 프로세스 종료까지 미완료 쓰기 보장은 제외 |
| 가격 정책 | 0 이하·누락 정가는 정보 없음 표시. 금액 필터 적용 시 제외·미적용 시 도서 유지, 원본 API·Room 값 보존. API가 0의 의미를 보장한다고 단정하지 않는 앱 정책 |
| 검증 범위 | 자동 테스트와 기기 검증을 구분. 동시 상세 진입·폴더블·태블릿을 확인 범위에 포함하되 현재 APK의 미실행 항목은 별도 표시 |
| 빌드 환경 | Metro와 daemon JDK 21 유지. 원문의 JDK 17 조건과 차이를 공개하고, 컴파일 대상 17을 실행 JDK 17로 설명하지 않음 |

## 참고 코드와 보안

참고 구조·출처·적용 범위는 [ARCHITECTURE](ARCHITECTURE.md) 기준입니다. 외부에서 확인한 UI 사례와 이 앱이 정한 내부 동작을 구분합니다.

API 키·인증정보·개인 이메일·원본 비공개 메시지는 문서와 Git에 넣지 않습니다. 제출용 `local.properties`는 Git에서 제외하며 사용자가 최종 패키지와 전달 대상을 확인합니다.

현재 Writer 제거 브랜치는 사용자가 별도 구현·테스트·Draft PR을 요청해 진행했습니다. 공통 Mutation actor의 직접 DAO 호출로 단순화하고, 실제 호출 경로의 상태·순서·수명·실패 테스트 및 국소 결함 주입으로 검증합니다. 새 결과와 포기한 actor 자체 취소 보장은 [Writer 제거 검증](WRITER_REMOVAL.md)에 구분합니다.
