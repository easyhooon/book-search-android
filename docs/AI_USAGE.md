# AI 활용

AI는 설계·구현·테스트·문서 작성에 활용했으며, 개발자가 기술과 제품 정책을 결정하고 결과를 검토했습니다. 최종 APK 빌드·자동 테스트 140개, Galaxy 핵심 기능과 제출 패키지를 검증했습니다. 네트워크 오류·태블릿·폴더블의 최신 APK 재검증은 미실행입니다. 검증 범위와 제한은 [QA](QA.md), 요구사항별 상태는 [REQUIREMENTS](REQUIREMENTS.md)에 있습니다.

## 활용 범위

| 도구 | 활용한 작업 |
| --- | --- |
| Codex | 요구사항·참고 자료 조사, 설계 초안과 코드·문서 대조, 개발자가 승인한 구현과 회귀 테스트 작성, 빌드·테스트 실행, 제출 준비 검토와 문서 정리 |
| Claude Code (Claude Opus 5.5) | 구현 사양 정리, Gradle·모듈 구성, 앱 코드와 테스트 작성, 실기기 QA 조작, 시연 영상 제작, 제출 ZIP 스크립트와 검증 문서 작성 |

개발자는 기술 선택, 화면 동작과 가격 정책, AI 결과의 채택·수정 여부, 실제 키 설정과 최종 제출 확인을 맡았습니다. 폴더블 확인에서는 실기기를 연결하고 직접 접고 펴는 동작도 수행했습니다. 코드·회귀 테스트 작성과 명령 실행을 AI에 맡긴 범위와 개발자가 직접 판단한 범위를 구분합니다.

## AI 결과를 검증한 방법

- **요구사항과 코드 대조:** 원문 필수 조건, 사용자 추가 요구, 제품 선택을 R-ID로 구분하고 구현·문서·제출 준비 상태를 대조했습니다. 라이브러리 동작은 공식 문서와 사용 중인 라이브러리 소스로 확인했습니다.
- **단위·계층 테스트:** ID·가격·필터 규칙, 검색 상태 전이와 페이지네이션, MockWebServer를 이용한 API 계약, Room 저장·관찰·DB 재열기를 자동 테스트로 확인하는 구성을 사용했습니다.
- **수명·통합 테스트:** 실제 Soil 연결을 포함하는 `SearchRetryTest`, 실제 retain·Soil·Writer와 Fake DAO를 연결한 `FavoriteMutationLifecycleTest`로 재시도, 접수한 저장 명령의 완료·순서·실패 격리·참조 정리를 검증했습니다. Fake DAO 검증을 실기기 Room 지연·실패 재현으로 간주하지 않습니다.
- **화면·상태 확인:** Compose 테스트로 내비게이션·retain·창 크기별 배치·상태 복원을 확인하고, 기기 QA로 회전·오프라인·프로세스 재생성·태블릿·폴더블을 보완했습니다. 이전 빌드의 기기 QA와 영상은 현재 코드의 실기기 검증 증거가 아닙니다.
- **실행 결과 확인:** 테스트 파일 작성 여부와 실제 실행 여부를 구분하고 명령·로그·실패 원인을 대조했습니다. 최종 소스의 자동 테스트 140개를 새로 실행해 실패·오류·건너뜀 0을 확인했습니다. 이후 문서 보완 중 앱 소스·빌드 설정의 동일성을 해시로 확인했습니다.

현재 원문의 JDK 17 빌드 실행 조건은 미충족입니다. 앱 컴파일 대상은 Java 17이지만 Metro 플러그인·컴파일러는 JDK 21을 요구하며, 현재 빌드·테스트도 daemon JDK 21에서 실행했습니다. 현재 구성과 제한은 [SPEC](SPEC.md)의 JDK 기준과 [QA](QA.md)에 설명합니다.

## AI 제안을 그대로 사용하지 않은 개발자 판단

| 주제 | 개발자의 판단과 최종 구현 |
| --- | --- |
| 화면 상태와 수명 | AI가 제안한 ViewModel 중심 구성 대신 학습 목표와 기존 검증 경험을 근거로 retain + Navigation 3를 선택했습니다. 별도 Store를 추가하지 않고 얇은 Presenter가 화면 상태를 소유하며, 객체 유지와 프로세스 복원 데이터를 구분합니다. |
| 데이터 접근 | Android 전용 과제의 HTTP 통신·테스트를 Retrofit·OkHttp로 충족해 Ktor 추가 이점이 없다는 판단으로 더 익숙한 Retrofit 선택. Soil key에 서비스를 주입하고 typed-key가 호출과 상태를 맡으므로 단순 전달용 Repository는 추가하지 않았습니다. 즐겨찾기의 단일 기준은 Room입니다. |
| 모듈 경계 | 원격·로컬 책임을 `core:network`와 `core:database`로 분리했습니다. 앱 코드 9개 모듈과 테스트 전용 모듈로 구성하고, 불필요한 플랫폼 추상화·자체 생성기는 추가하지 않았습니다. |
| 상세 복원과 저장 수명 | Kakao API에 단건 조회가 없어 상세 스냅샷을 내비게이션 키에 저장합니다. 저장 버튼을 누른 뒤 화면 이동은 허용하되 접수한 요청은 완료 후 정리합니다. 프로세스 종료까지 쓰기 완료를 보장하지는 않습니다. |
| 가격 | 0 이하·누락 정가는 정보 없음으로 표시하고 금액 필터를 적용할 때 제외합니다. 필터 미적용 시 도서는 유지하며 원본 API·Room 값도 보존합니다. API가 0의 의미를 보장한다고 단정하지 않는 앱 정책입니다. |
| 검증 범위 | 자동 테스트만으로 기기 동작까지 완료 판정하지 않습니다. 상세 동시 진입, 실제 폴더블 접힘·펼침, 태블릿 2-pane도 확인 대상으로 정했습니다. 최종 APK의 Galaxy 핵심 기능은 확인했고, 네트워크 오류·태블릿·폴더블 재검증은 미실행으로 구분했습니다. |
| 빌드 환경 | 현재 선택한 Metro와 JDK 17 요구의 충돌을 미충족 사항으로 공개합니다. 수동 DI나 테스트 SDK 변경은 적용하지 않았습니다. |

## 참고 코드와 보안

참고 구조와 출처·적용 범위는 [ARCHITECTURE](ARCHITECTURE.md)에 정리했습니다. 공개 UI 사례와 이 앱이 정한 내부 동작을 구분하며, 참고 구조를 그대로 복사한 것으로 설명하지 않습니다.

API 키·인증정보·개인 이메일·원본 비공개 메시지는 문서와 Git에 넣지 않습니다. 제출용 `local.properties`는 Git에서 제외하며 사용자가 최종 패키지와 전달 대상을 확인합니다.
