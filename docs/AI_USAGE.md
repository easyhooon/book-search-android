# AI 활용

AI는 설계·구현·테스트·문서 작성에 활용했으며, 개발자가 기술과 제품 정책을 결정하고 결과를 검토했습니다. 개발자 승인에 따른 수동 DI·JDK 17 비교 브랜치에서 APK 빌드와 자동 테스트 149개가 통과했습니다. 제출 당시의 140개 테스트·Galaxy 핵심 기능·제출 패키지 결과와 구분하며, 이 브랜치의 API 36·37 실기기·새 Studio ZIP·새 PC 빌드·동적 재구성 측정은 미실행입니다. 검증 범위와 제한은 [QA](QA.md), 요구사항별 상태는 [REQUIREMENTS](REQUIREMENTS.md)에 있습니다.

## 활용한 작업

| 도구 | 맡은 작업 |
| --- | --- |
| Codex | 요구사항·참고 자료 조사, 설계 초안, 코드·문서 대조. 개발자가 승인한 앱 코드·회귀 테스트 작성과 실행, 빌드, 제출 준비 검토, 문서 정리 |
| Claude Code (Claude Opus 5.5) | 구현 사양, Gradle·모듈 구성, 초기 앱 코드·테스트, 실기기 QA 조작, 시연 영상, 제출 ZIP 스크립트·검증 문서 |

개발자의 역할은 기술 선택, 화면 동작·가격 정책, AI 결과 검토, 실제 키 설정과 최종 제출 확인입니다. 실기기 연결과 폴더블을 직접 접고 펴는 동작도 개발자가 수행한 범위입니다. 앱 코드·회귀 테스트 작성과 명령 실행을 AI에 맡긴 범위와 구분합니다.

## AI 결과를 검증한 방법

자동 테스트는 이 브랜치에서 다시 실행했습니다. 기기 QA·영상·Studio ZIP 결과는 main 또는 이전 빌드의 참고 자료로 구분합니다.

- **요구사항과 코드 대조:** 원문 필수 조건, 사용자 추가 요구, 제품 선택을 R-ID로 구분하고 구현·문서·제출 준비 상태를 대조했습니다. 라이브러리 동작은 공식 문서와 사용 중인 라이브러리 소스로 확인했습니다.
- **단위·계층 테스트:** ID·가격·필터 규칙, 검색 상태 전이와 페이지네이션, MockWebServer를 이용한 API 계약을 확인했습니다. Room 구독은 실제 in-memory Room으로, 영속성은 별도 파일 DB 재열기로 검증했습니다.
- **수명·통합 테스트:** 실제 Soil 연결을 포함하는 `SearchRetryTest`, 실제 retain·Soil·Mutation key와 Fake DAO를 연결한 `FavoriteMutationLifecycleTest`로 재시도, 접수한 저장 명령의 완료·순서·실패 격리·참조 정리를 검증했습니다. Fake DAO 검증을 실기기 Room 지연·실패 재현으로 간주하지 않습니다.
- **수동 DI 검증:** `ManualAppGraphTest` 4개로 앱·화면 객체의 공유 범위, 공통 Mutation ID, 세 화면이 실제 Room의 같은 데이터를 읽고 쓰는 연결을 확인했습니다. 이 테스트는 기존 Soil·retain 수명 테스트를 보완합니다.
- **화면·상태 확인:** Compose 테스트로 내비게이션·retain·창 크기별 배치를 확인하고 `StateRestorationTester`로 저장 상태 복원을 모사했습니다. 실제 프로세스 종료 검증은 아닙니다. 회전·오프라인·프로세스 재생성·태블릿·폴더블의 기존 기기 QA와 영상은 이 브랜치의 실기기 검증 증거가 아닙니다.
- **실행 결과 확인:** 테스트 XML 30개와 실행 로그를 대조해 main의 145개·수동 DI 4개를 모두 새로 실행했고 실패·오류·건너뜀은 0임을 확인했습니다. 외부 init script로 실제 daemon Oracle JDK 17.0.10과 9개 테스트 작업의 JVM 17 실행을 확인했습니다. 현재 실행 결과는 [수동 DI 최신화 검증](MANUAL_DI_UPDATE.md)에 기록합니다.

main은 Metro·daemon JDK 21·Robolectric SDK 36 구성입니다. 이 브랜치는 수동 DI·daemon JDK 17·Robolectric SDK 35로 검증했으며 compileSdk·targetSdk 37은 유지합니다. SDK 35 테스트 결과를 API 36·37 실기기 검증으로 간주하지 않습니다([SPEC](SPEC.md), [QA](QA.md)).

## AI 제안을 그대로 사용하지 않은 개발자 판단

| 주제 | 판단과 구현 |
| --- | --- |
| 화면 상태와 수명 | AI가 제안한 ViewModel 중심 구성 대신 학습 목표와 기존 검증 경험을 근거로 retain + Navigation 3를 선택했습니다. 별도 Store를 추가하지 않고 얇은 Presenter가 화면 상태를 소유하며, 객체 유지와 프로세스 복원 데이터를 구분합니다. |
| 데이터 접근 | Android 전용 과제의 HTTP 통신·테스트를 Retrofit·OkHttp로 충족해 Ktor 추가 이점이 없다는 판단으로 더 익숙한 Retrofit 선택. Soil key에 서비스를 주입하고 typed-key가 호출과 상태를 맡으므로 단순 전달용 Repository는 추가하지 않았습니다. 즐겨찾기의 단일 기준은 Room입니다. |
| 모듈 경계 | 원격·로컬 책임을 `core:network`와 `core:database`로 분리했습니다. 앱 코드 9개 모듈과 테스트 전용 모듈로 구성하고, 불필요한 플랫폼 추상화·자체 생성기는 추가하지 않았습니다. |
| 상세 복원과 저장 수명 | Kakao API에 단건 조회가 없어 상세 스냅샷을 내비게이션 키에 저장합니다. 저장 버튼을 누른 뒤 화면 이동은 허용하되 접수한 요청은 완료 후 정리합니다. 프로세스 종료까지 쓰기 완료를 보장하지는 않습니다. |
| 가격 | 0 이하·누락 정가는 정보 없음으로 표시하고 금액 필터를 적용할 때 제외합니다. 필터 미적용 시 도서는 유지하며 원본 API·Room 값도 보존합니다. API가 0의 의미를 보장한다고 단정하지 않는 앱 정책입니다. |
| 검증 범위 | 자동 테스트만으로 기기 동작까지 완료 판정하지 않습니다. 이 브랜치의 자동 테스트 통과와 main APK의 Galaxy 확인을 분리하고, API 36·37 실기기·새 Studio ZIP·새 PC·동적 재구성 측정은 미실행으로 남겼습니다. |
| 빌드 환경 | JDK 17 조건을 비교하기 위해 수동 DI·Robolectric SDK 35 변경 승인. AppGraph·화면 Factory·retain·Soil의 경계를 유지하고 compileSdk 37 고정. 객체 조립과 공유 수명을 직접 관리하는 비용 수용, API 36·37 기기 검증과 구분 |

## 참고 코드와 보안

참고 구조·출처·적용 범위는 [ARCHITECTURE](ARCHITECTURE.md) 기준입니다. 외부에서 확인한 UI 사례와 이 앱이 정한 내부 동작을 구분합니다.

API 키·인증정보·개인 이메일·원본 비공개 메시지는 문서와 Git에 넣지 않습니다. 제출용 `local.properties`는 Git에서 제외하며 사용자가 최종 패키지와 전달 대상을 확인합니다.

현재 Writer 제거 브랜치는 사용자가 별도 구현·테스트·Draft PR을 요청해 진행했습니다. 공통 Mutation actor의 직접 DAO 호출로 단순화하고, 실제 호출 경로의 상태·순서·수명·실패 테스트 및 국소 결함 주입으로 검증합니다. 새 결과와 포기한 actor 자체 취소 보장은 [Writer 제거 검증](WRITER_REMOVAL.md)에 구분합니다.
