# QA 테스트케이스와 실기기 실행 결과

[요구사항](REQUIREMENTS.md)의 R-ID를 기준으로 사용자 시나리오를 만들어 실기기에서 실행한 기록입니다. 자동 테스트로 확인한 항목과 기기에서 직접 확인한 항목을 구분합니다. 여기의 "통과"는 아래 환경에서 실제로 실행해 본 결과만 뜻합니다.

## 실행 환경

| 항목 | 값 |
| --- | --- |
| 기기 | Samsung SM-S936N, Android 17(API 37), 1080x2340, density 450 |
| 빌드 | debug APK. 최종 확인 커밋 `22855b3`(결함 수정 2건 포함) |
| 일시 | 2026-10-07 ~ 2026-10-08 |
| 조작 | `adb shell input`(tap·swipe·text·keyevent)으로 화면 조작 |
| 판정 근거 | `screencap` 스크린샷, `uiautomator dump`의 화면 텍스트·설명, OkHttp 로그의 `--> GET` 요청 수, `dumpsys`(활성 Activity·키보드 표시 여부) |
| 기기 설정 변경 | 사용자 허락을 받고 회전·다크 모드·비행기 모드·화면 크기를 바꿨고, 끝난 뒤 원래 값으로 되돌렸습니다(자동 회전 켬, 라이트 모드, 비행기 모드 끔, 1080x2340·450) |

스크린샷은 [qa/](qa/) 폴더에 있습니다. 파일 이름의 `tcNN`이 아래 표의 TC 번호입니다.

## 결과 요약

- 실기기 시나리오 31건을 실행했습니다. 최종 빌드 기준으로 모두 통과입니다.
- 실행 중 결함 2건을 찾았습니다. 재현 테스트를 먼저 작성하고, 수정 전 코드에서 실패하는 것을 확인한 뒤 고쳤습니다. 고친 빌드로 같은 절차를 다시 실행해 통과를 확인했습니다.
- 단위·Compose·Room 자동 테스트는 110개이고 실패는 0개입니다(아래 "자동 테스트" 참고).

## 제약과 미실행 항목

- **동시 탭:** adb로는 진짜 멀티터치를 만들 수 없습니다. TC-85는 탭 하나를 백그라운드로 보내고 다른 탭을 바로 보내 거의 동시에 들어가게 했습니다. 두 손가락 동시 입력은 `BookSearchNavHostTest`의 Compose 테스트가 대신합니다.
- **연타·쓰기 중 뒤로:** TC-67, TC-71은 한 번의 셸 호출로 입력을 이어 보냈지만 입력 간격은 수십~수백 ms입니다. 어느 탭이 쓰기 중 비활성으로 무시됐는지는 기기에서 구분하지 않았고, 최종 상태 일치만 확인했습니다. 쓰기 순서와 취소 경계는 단위 테스트로 확인합니다.
- **Room 쓰기 실패(R-028, R-067):** 실기기에서 DB 오류를 만들지 않았습니다. Fake writer로 실패를 주입한 Presenter·`FavoriteToggler` 테스트로 확인합니다.
- **폴더블:** 실제 폴더블 기기나 폴더블 AVD의 접힘·펼침은 실행하지 않았습니다. TC-35·68c의 `wm size` 변경으로 창 크기 변화만 흉내 냈습니다. 힌지 자세 같은 폴더블 고유 상태는 미검증입니다.
- **프로세스 종료:** `am kill`로 백그라운드 프로세스를 종료했습니다. 시스템이 메모리 부족으로 종료하는 경우와 같은 경로(저장된 상태로 Activity 재생성)이지만, 실제 메모리 압박은 만들지 않았습니다.
- **텍스트 입력:** `adb input text`로 가격을 넣은 직후 시트를 닫으면 키보드가 다시 뜨는 현상이 있었습니다. 실제 키패드를 터치해 같은 흐름을 다시 해 보니 재현되지 않아 adb 입력의 부작용으로 판단했습니다(TC-13은 키패드 터치로 다시 실행).
- **네트워크 재연결:** TC-42에서 연결이 돌아와도 자동으로 다시 요청하지 않는 것을 확인했습니다. 지금은 재시도 버튼이 복구 수단입니다([SPEC](SPEC.md) 9절).
