# 요구사항 체크리스트

기준일: 2026-10-07. 아래 체크는 모두 미완료입니다. 요구사항을 문서에 적었다는 이유로 구현 항목을 완료 처리하지 않습니다.

- **필수**: 제공된 과제 조건
- **선택 결정**: 사용자가 선택한 기술 방향
- **권장**: 필수 조건을 안정적으로 달성하기 위한 제안
- **미정**: 세부 의미나 구현 방식이 아직 확정되지 않은 항목

## 1. 환경과 빌드: 필수

- [ ] Kotlin, Kotlin Coroutines, Flow, Jetpack Compose 사용
- [ ] Gradle 9.4.1
- [ ] Android Gradle Plugin 9.2.1
- [ ] Kotlin 2.4.0
- [ ] KSP를 사용하는 경우 2.3.10
- [ ] JDK 17
- [ ] compileSdk 37
- [ ] 최신 안정 Android Studio에서 열기 및 빌드 확인
- [ ] Gradle Wrapper 파일과 실행 권한 포함
- [ ] 별도 설명 없이도 재현 가능한 `./gradlew assembleDebug` 성공
- [ ] 요청 버전 조합의 호환성 확인. 충돌 시 임의 변경하지 않고 실패 로그·공식 근거·대안 기록

위 버전은 제공된 요구값입니다. 현재 저장소에서 검증된 설치 버전이나 성공한 빌드 결과가 아닙니다. minSdk, targetSdk, Compose/Navigation/Room/Ktor 버전은 아직 확정하지 않았습니다.

## 2. 원격 도서 검색: 필수

- [ ] 검색 탭과 즐겨찾기 탭 제공
- [ ] Kakao 책 검색 API에 검색어 전달
- [ ] 정확도순 / 최신순 선택. API 값은 `accuracy` / `latest`, 최신순 의미는 발간일순
- [ ] 페이지당 20개 요청 및 다음 페이지 로드
- [ ] 카드에 표지, 제목, 저자, 출판사, 출판일, 가격 표시
- [ ] 카드에서 즐겨찾기 추가·해제
- [ ] 카드를 선택하면 상세 화면으로 이동
- [ ] 검색·정렬 변경 후 이전 조건의 결과가 섞이지 않음
- [ ] 검색 결과 없음 / 최초 로딩 / 최초 오류 / 추가 로딩 / 추가 오류 구분

API 계약 근거: [Kakao 책 검색 REST API](https://developers.kakao.com/docs/ko/daum-search/dev-guide#search-book).

## 3. 즐겨찾기: 필수

- [ ] 도서 정보를 로컬에 영속 저장
- [ ] 앱 종료 및 재실행 후 즐겨찾기 유지
- [ ] 즐겨찾기 목록 안에서 로컬 검색
- [ ] 제목 오름차순 / 내림차순 정렬
- [ ] 가격 조건 필터
- [ ] 즐겨찾기 목록에서 상세로 이동
- [ ] 검색·즐겨찾기·상세에서 동일 도서의 즐겨찾기 상태 일치
- [ ] 저장/삭제 실패 시 성공으로 표시하지 않음

### 아직 확정되지 않은 세부 의미

- 가격 필터의 정확한 UI와 범위는 원 요구사항에 명시되지 않았습니다. **권장안은 정가 기준 최소·최대 금액(양끝 포함)**입니다. 가격이 0인지 여부만으로 거르는 필터는 가격 조건 요구를 충분히 보여주지 못합니다.
- 로컬 검색 범위는 제목 우선으로 제안합니다. 저자·출판사까지 확장할지는 구현 전 결정하고 README에 씁니다.
- 가격 미제공·음수 값은 가격 없음으로 처리하는 안을 제안합니다. 0원은 자동으로 정보 없음으로 단정하지 않습니다. 범위 미설정 시 가격 없음 포함, 범위 설정 시 제외하는 정책과 0원 취급을 함께 명시합니다.
- 정가/판매가 중 필터 기준, 공백 검색, 한글·영문 혼합 정렬, 최소값이 최대값보다 큰 경우의 안내를 확정합니다.

## 4. 상세 화면: 필수

- [ ] 도서 표지와 제목 등 도서 정보 표시
- [ ] 즐겨찾기 상태 표시 및 변경
- [ ] 목록과 상세의 즐겨찾기 변경 결과 일치
- [ ] 저장된 도서는 네트워크 없이도 로컬 정보로 상세 표시
- [ ] 누락된 표지·저자·날짜·가격 등으로 화면이 깨지지 않음

저장된 표지 URL만으로 오프라인 이미지 표시가 보장되지는 않습니다. 텍스트 정보는 DB로 보장하고, 이미지 캐시가 없으면 대체 이미지를 보여줍니다. 오프라인에서도 원본 표지를 반드시 보장하려면 이미지 파일 저장을 추가 설계해야 합니다.

## 5. 품질과 확장성: 필수 고려사항

- [ ] 불안정한 네트워크에서도 앱 사용 가능
- [ ] 오류 후 재시도 가능, 추가 로딩 오류가 기존 목록을 제거하지 않음
- [ ] 태블릿·폴더블 및 크기 변경 고려
- [ ] 대규모 앱의 기능 중 하나라는 전제로 구조 설계
- [ ] 여러 개발자가 확장할 수 있는 책임·의존성 경계 설명
- [ ] 구현한 설계의 선택 이유와 단점 설명
- [ ] 검토했으나 구현하지 않은 대안과 미구현 범위 설명

오프라인 즐겨찾기·상세는 기본 범위입니다. 원격 검색 결과 전체를 디스크에 보관하고 재시작 후 제공하는 기능은 명시된 필수 요구사항이 아닙니다. 초기 범위는 온라인 검색, 메모리 내 기존 결과 유지, 오류/재시도, 로컬 즐겨찾기 사용입니다. 영속 검색 캐시는 핵심 기능 검증 후 선택합니다.

## 6. 선택 결정과 권장 설계

- [ ] **사용자 선택**: retain + Navigation 3로 진행. 학습 목표를 유지하며 검증
- [ ] **허용된 권장안**: Room으로 영속 저장. Room 자체가 필수 기술인 것은 아님
- [ ] **권장**: Room Flow를 즐겨찾기의 단일 상태 기준으로 사용
- [ ] **검토 중**: Ktor 재사용 및 커스텀 페이지네이션 / Paging 3 비교
- [ ] **권장**: 기능·데이터 경계를 작게 유지하고 불필요한 모듈 증설 피하기
- [ ] **권장**: query/sort/filter/bookId 등 최소 복원 값만 saveable 상태로 보관

## 7. 우선 검증 시나리오

- [ ] 검색어 빠른 변경, 정렬 변경, 빈 검색어로 초기화
- [ ] 마지막 페이지가 20개여도 `meta.is_end`에 따라 요청 종료
- [ ] 추가 로딩 실패 후 같은 페이지 재시도, 중복 트리거 차단
- [ ] 페이지 간 동일 ISBN 중복 제거
- [ ] 가격 경계값, 0원/가격 없음, 잘못된 범위, 필터 결과 0개
- [ ] 오프라인 즐겨찾기·상세 및 앱 재시작 후 복원
- [ ] Room 쓰기 실패, 즐겨찾기 연타, 쓰기 중 뒤로 가기
- [ ] 화면 회전, 창 크기 변경, 폴더블 펼침·접힘
- [ ] 상세 진입·복귀 시 상태 유지, 백스택 제거 시 작업 정리
- [ ] 프로세스 종료 후 최소 상태와 저장 도서 복원
